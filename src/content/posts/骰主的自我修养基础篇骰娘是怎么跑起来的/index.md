> **前言**
> 相信对于大多数跑团玩家来说，骰子都是重要的工具。而对于大部分在线上使用 QQ 等平台跑团的玩家来说，骰娘已经成为了跑团必不可少的正（背）义（刺）伙（灌）伴（铅）。当下骰娘框架已经逐渐成熟，搭建一个自己的骰娘已经不再是什么困难的事情，但是对于很多先前从未接触计算机的骰主来说，完全无法理解骰娘到底是如何跑起来的，出了问题也很难找到解决思路。常常即使有不当「伸手党」想要自己解决，也会因为无法定位自己问题原因在大量文档中迷失自己的现象。
> 
> 为了帮助有学习意向的骰主解决这些问题，在本文中我将用尽量通俗易懂的语言来讲述一些骰主需要了解的技术基础知识，帮助骰主更好地管理自己的骰娘，不被技术所困扰。
> 
> 本文中的骰系框架不针对特定框架，为了方便，本文中我们以海豹系（sealdice）为例进行说明。不同框架之间的术语可能与本文有一定出入，请读者自行查找骰系的手册。
> 
> 本文中提到的骰娘若无特殊说明，是通过官方或者第三方方式接入聊天平台并提供跑团功能支持的机器人，大部分语境下特指使用第三方方式接入 QQ 平台的跑团机器人。本文讲述的大部分内容同样适用于其他功能的机器人部署。
>
> 本文默认读者拥有基础计算机使用能力，知道什么是文件，什么是解压缩，什么是扩展名和文件格式，请确保你在阅读之前了解这些知识。

骰娘的搭建早已不是什么难事了，很多时候只需要下载文件解压好后双击即可运行，然后打开配置界面用骰娘的 QQ 账号扫码登录，你就得到了一只属于自己的骰娘。那么，骰娘到底是怎么工作的呢？

## 从骰娘要做什么看骰娘的组成

首先，我们需要搞清楚一点，从我们发送一条指令到骰娘响应我们的指令这一过程中究竟发生了什么。请看下面的聊天记录：

![骰娘响应 ra 指令](https://picbed.sheyiyuan.cn/i/2025/10/04/hfsmio.png)

我们可以看到，骰娘在这个过程中接收了我们的指令，并按照指令帮助我们完成检定，然后将检定的结果通过 QQ 发送到收到指令的群聊。我们很容易想到：

- 骰娘能“看到”和“发送”QQ 消息，说明骰娘能够与 QQ 交互。
- 骰娘能够“听懂”我们的指令需要进行什么操作，说明骰娘有解析并执行命令的能力。
- 骰娘能够“记住”我们先前录入的内容，比如这里骰娘知道我的侦查是 50%，说明骰娘具有记录的能力。

显然，骰娘要能够响应我们的这一条指令，就至少需要具备以上三个不同的能力。大家可以花 5 秒钟猜一猜，哪一个能力是最难以实现的。

很明显，最难实现的部分是 **与 QQ 的交互**。因为骰娘本身作为机器人显然不能直接“看懂”QQ 上的消息，需要一个程序把这些消息翻译成骰娘能够理解的“语言”。此外如果使用第三方程序来读取 QQ 是违规的 **外挂** 程序。实际上，我们常说的的骰没了、骰掉了乃至骰娘账号被风控甚至冻结封禁就是这一步上出现了问题。

可能有些读者会疑问为什么我们不使用官方提供的机器人渠道来搭建骰子。总结下来就是：门槛高，效果差，限制多。如果要抨击 QQ 官方的机器人接口，我大可以写几万字的长文来痛斥腾讯的罪状，这里由于篇幅限制就略过了。

为了和 QQ 的监管斗智斗勇，往往需要不断针对最新版本的 QQ 优化这些与 QQ 交互的第三方程序，使得这一部分功能往往需要及其频繁的更新，并且很多骰娘以外的 QQ 机器人也需要这类程序来运行。此外骰娘如果要运行在 QQ 以外的平台，也需要类似的程序进行交互。于是开发者们干脆将这一部分单独拎出来，作为独立的程序运行。这个程序我们把它叫做 **协议**，通常这类程序都遵循一种叫做 `onebot` 的约定[^1]进行信息的传输，相当于把 QQ 或其他平台上原本骰娘不能看懂的话翻译成了 `onebot` 这种「语言」，而骰系的开发者们只需要「教会」骰娘使用这门「语言」即可。

[^1]: `onebot` 是一个开源的机器人协议规范，旨在提供一个统一的接口，使得机器人开发者可以更方便地与各种聊天平台进行交互。尽管 `onebot` 本身因为历史包袱让其对很多现代化的特性支持不佳，并且正在逐步被 `milky` 等新协议取代，但目前仍然被广泛使用。

有了协议一层的翻译，剩下的部分实际上就和平台完全没有关系了。骰娘只需要能够理解指令、存取数据，进行运算即可。这个具体的实现就对应我们常说的各种 **骰系**。

简单总结一下，骰娘就由两个部分组成，一个是骰系，一个是协议。当然，这种说法并不完全准确，大部分骰系往往会内置一个或者多个协议，如 `NapCat`、`Lagrange` 等，这些已经为用户封装好，让用户可以开箱即用。这些也就是常说的「内置客户端」，比如海豹系的内置客户端使用 `Lagrange` 协议，其他一些骰系可能使用 `NapCat` 协议。对于用户来说，内置客户端的好处就是开箱即用，不需要自己去搭建协议了；坏处就是如果内置客户端出现问题了，用户就只能等开发者修复了。

接下来我们再对骰系内的工作原理作一个简单分析。

我们刚才已经分析了，骰系本身需要和协议进行交互，来实现与 QQ 的交互。除此之外，骰系还需要实现指令解析、数据存取、运算等功能。我们可以把这些功能抽象成三个模块[^2]：

[^2]: 这三个模块的划分并不是官方的规定，是本文为方便读者理解进行的抽象逻辑划分，不同的骰系可能会有不同的实现方式，但大体上来说，这三个模块是比较常见的。同时由于篇幅所限，这里我们不对这三个模块进行过于细致的分析，读者如果有兴趣可以自己去查阅相关文档来了解更多细节。

- **指令解析模块**：负责解析用户输入的指令，理解用户的意图，并将其转换为骰娘能够执行的操作。同时这里通常也控制着指令是否启用。
- **数据存取模块**：负责存储和管理用户的数据，比如角色信息、技能数值等，以及在需要的时候能够快速地读取这些数据。
- **业务逻辑模块**：负责实现具体的游戏规则和逻辑，比如如何进行检定、如何计算伤害等。

这三个模块在骰系内不一定是完全独立的，但是一般来说都会有比较清晰的分工。

对于海豹来说，这三个模块分别由不同的组件实现，共同构成了海豹系的核心功能。我们的自定义回复和自定义插件功能是建立在这些模块之上的。

一般来说，骰娘协议正常连接时出现某些指令或者在某些组群内的指令不响应、响应数据异常等问题，往往就是骰娘的内部出现了问题。这时候我们可以先排查一下相关指令是否开启，骰娘在组群内是否开启。如果确认这些都没有问题了，再进一步根据日志进行排查或向他人求助。

## 公网？IP？端口？这些到底是什么？

你有没有想过，为什么下面这句提问会让很多大佬沉默？

> 「我的骰娘面板是 http://localhost:3211 ，请帮我看看我的配置。」

为什么这个问题会让很多大佬沉默呢？因为这句话里有一处明显的错误，那就是 `localhost`。`localhost` 是一个特殊的地址，指的是「本地计算机」，也就是说如果你在自己的电脑上访问 `http://localhost:3211`，你访问的就是你自己的电脑上的这个地址，而不是其他人的电脑上的这个地址。

简单来说，就像是别人问你你在哪里，你说「我在家里」，但是别人并不知道你家在哪里，所以别人就无法找到你一样。`localhost` 就是「我在家里」，而不是「我在某个具体的地址上」。

同样的，如果你在服务器上部署了一个骰娘，你同样不能使用 `localhost` 来访问它，因为 `localhost` 只指向你自己的电脑，而不是服务器上的那个骰娘。

类似的还有 `127.0.0.1`，它也是指向本地计算机的地址。

这个时候我们就需要使用服务器的公网 IP 地址来访问了。公网 IP 地址是一个唯一的地址，指向互联网上的一个具体的设备或者服务器。只有当你使用了公网 IP 地址，你才能通过这个地址来访问你的骰娘。






## API、HTTP、WebSocket ——骰娘与外界的沟通方式

我们在前面提到，骰娘需要与协议进行交互来实现与 QQ 的交互，那么骰娘和协议之间是如何进行沟通的呢？这时候就要提到一些比较专业的术语了，比如 API、HTTP、WebSocket 等等。

虽然看起来这些术语比较专业，但其实它们的原理并不难理解。我们可以把它们想象成不同的「通信方式」，就像我们平时用手机打电话、发短信、发微信一样，不同的通信方式有不同的特点和适用场景。

### API 是什么？
API（Application Programming Interface）是一种接口规范，定义了不同软件组件之间如何进行交互。API 不是一个具体的技术实现，而是一种约定，告诉开发者如何调用某个功能或者获取某些数据。就好比我们平时用手机打电话一样，电话就是一个 API，告诉我们如何拨打、接听、挂断等操作。

在实际骰娘搭建和开发过程中，我们一般有以下两种常见的 API：
- **网络 API**：一般指用骰娘访问第三方服务提供的接口，很多图片获取、AI 接入等功能都是通过网络 API 来实现的。
- **本地 API**：一般指骰娘内部提供的接口，供插件或者其他组件调用的接口，比如获取角色信息、进行检定等功能。如果你不进行插件开发的话，这些接口你是完全不需要了解的。

这里我们再进一步解释一下网络 API 是如何工作的。

API 调用可以理解为一个请求-响应的过程。举个例子，我们在去取快递的时候，需要根据我们的地址来找到最近的快递驿站，然后到达驿站后我们出示我们的快递单号和取件码，快递员核对信息后把快递交给我们。这个过程就可以看作是一个 API 调用的过程，我们的地址就是请求地址（URL），快递单号、取件码就是请求参数（request parameters），快递员核对信息后把快递交给我们就是响应结果（response）。

为什么我们需要用到 API 呢？因为很多功能需要依赖第三方服务来实现，比如图片获取、AI 接入等，这些服务提供商通常会提供一个 API 供我们调用，这样我们就可以通过调用这个 API 来获取我们需要的功能或者数据了。

### HTTP 和 WebSocket 是什么？
在协议的配置页面，我们经常会看到 HTTP 和 WebSocket 这两个选项，这两者都是协议与骰娘进行通信的方式。它们的区别在于通信的方式和效率。

HTTP（HyperText Transfer Protocol）和 WebSocket 是两种不同的通信协议，都是用来实现网络通信的。

这两者主要出现在骰娘与协议进行交互的过程中。HTTP 是一种无状态的请求-响应协议，适用于一次性的请求和响应，比如我们访问一个网页的时候就是通过 HTTP 协议来进行通信的。而 WebSocket 是一种全双工通信协议，允许客户端和服务器之间进行实时的双向通信，适用于需要频繁交互的场景，比如在线聊天、游戏等。

聪明的你看到这里一定已经知道了，骰娘与协议之间的通信方式通常以 WebSocket 为主，因为骰娘需要实时地接收和响应来自 QQ 的消息，而 HTTP 这种一次性的请求-响应方式更适合一些插件发起一次性的请求。

### 正向和反向
协议配置的选项除了 HTTP 和 WebSocket 之外，还有一个正向和反向的选项和它们排列组合，这个选项是用来指定骰娘与协议之间的通信方式的。

- **正向**：指骰娘主动连接协议，通常是通过 WebSocket 来实现的。这种方式的好处是配置简单，适合大多数用户使用。但是如果协议所在的服务器在公网上，可能会存在安全风险，这也是之前发生的多起 NapCat 攻击事件。
